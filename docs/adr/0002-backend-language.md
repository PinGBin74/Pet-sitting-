# 2. Язык и каркас серверной части

- **Статус**: предложено
- **Дата**: 2026-11-06
- **Участники**: Ирина, Артур, Антон

## Движущие факторы

- `C-04`: команда из трёх человек, один семестр — объём, который реально освоить, важнее скорости исполнения
- `NFR-05`: прогон тестов не дольше 60 секунд — требует языка с быстрым запуском и лёгкими тестами
- `FR-*`: контракт API понадобится в ЛР 4Б — предпочтителен каркас, формирующий описание OpenAPI сам
- `NFR-01`: 95 % запросов быстрее 300 мс при 100 хостах — **не различает варианты**: при таком объёме все три подходят

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| **Python 3.13 + FastAPI** | Проверка данных и описание API из коробки; низкий порог входа; язык знаком с первого курса | Скорость исполнения ниже; ошибки типов ловятся отдельным инструментом |
| Go + net/http | Высокая скорость; статическая типизация; простое развёртывание | Многословнее; описание API и проверка данных пишутся руками |
| C# + ASP.NET Core | Сильная платформа; развитая среда разработки | Тяжелее окружение; на занятиях используются три разных системы |

## Решение

**Python 3.13 + FastAPI.**

**Определяющий довод** — объём, который команда успевает освоить за семестр: проверка данных, описание API и внедрение зависимостей даются каркасом, а не пишутся самостоятельно.

## Последствия

**Положительные.** Модели `pydantic` переиспользуются как проверка данных и как описание OpenAPI (ЛР 4Б). Асинхронность доступна без дополнительных библиотек (ЛР 6А).

**Отрицательные.** Проверка типов — отдельный этап конвейера (`mypy`); без него аннотации остаются документацией. Для задач, чувствительных к скорости исполнения, язык не подошёл бы — в объёме курса такие задачи не возникают.

**Что заставит пересмотреть решение.** Требование обрабатывать десятки тысяч запросов в секунду на одном экземпляре, либо необходимость поставлять систему единым исполняемым файлом без среды исполнения.
