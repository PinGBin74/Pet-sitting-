# 4. Короткий подписанный маркер доступа и отзываемый обновляющий маркер

## Контекст

Нужно выбрать способ проверки подлинности и управления правами. В системе три роли: владелец питомца, хост и модератор. Один человек может быть и владельцем, и хостом. Права в основном определяются **принадлежностью**: бронь — владельцу и хосту этой брони, карточка — владельцу, решение о проверке — только модератору.

## Движущие факторы

- `NFR-02`: все операции, кроме поиска и публичного профиля, требуют маркера; срок жизни не более 15 минут; владелец видит только своё; чужой объект — `404`
- `NFR-02`: выход из системы и смена пароля должны прекращать доступ — иначе потерянный телефон даёт доступ к адресам и фото питомцев
- `C-06`: внешние платные службы не используются
- `NFR-05`: решение не должно добавлять службу в окружение
- Клиенты API — браузерное приложение, тесты API и описание OpenAPI: способ передачи маркера должен быть одинаков для всех
- `NFR-01`: 95 % поисков не дольше 300 мс — **не различает варианты**: поиск открыт без маркера, а проверка маркера на остальных операциях стоит доли миллисекунды в любом варианте

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Сессия на сервере: идентификатор в cookie, состояние в PostgreSQL | Отзыв мгновенный; в cookie нет данных | Обращение к базе на каждый запрос; cookie на всех изменяющих запросах требует защиты от подделки межсайтовых запросов (CSRF); тестам и OpenAPI неудобно |
| **Подписанный маркер доступа (JWT) на 15 минут и обновляющий маркер, хранимый в базе как хеш** | Проверка маркера доступа без хранилища; заголовок `Authorization: Bearer` одинаков для браузера, тестов и OpenAPI; выход и смена пароля отзывают обновляющий маркер | Маркер доступа нельзя отозвать до истечения 15 минут; два вида маркеров — сложнее реализация |
| Только подписанный маркер, обновляющий тоже подписан и не хранится | Нет состояния вообще | Выход ничего не отменяет в течение срока обновляющего маркера — 7 дней; нарушает второй пункт `NFR-02` |
| Внешний поставщик (OpenID Connect: VK ID, Яндекс ID) | Пароли у нас не хранятся | Внешняя зависимость и регистрация приложения на учебном стенде без постоянного домена; роль модератора всё равно хранится у нас |
| Ключ API | Проще всего | Не годится для людей: нет срока и роли, ключ долгоживущий |

## Решение

- **Маркер доступа**: JWT, подпись HS256 секретом из переменной окружения, срок **15 минут**. В маркере только `sub` (идентификатор пользователя), `roles` (`moderator`, если назначен) и `exp`. Передаётся заголовком `Authorization: Bearer`; в браузере хранится в памяти, не в `localStorage`.
- **Обновляющий маркер**: случайная строка, срок **7 дней**, в базе хранится только хеш. При каждом обновлении заменяется новым (ротация); выход и смена пароля удаляют его. В браузере — cookie `HttpOnly; Secure; SameSite=Strict`, путь только `/v1/auth/refresh`.
- **Права**: роль модератора — из маркера; права владельца и хоста — сравнением `sub` с владельцем или хостом записи **на сервере**. Отдельных ролей «владелец» и «хост» нет: хост — это пользователь, у которого есть профиль хоста.
- **Защищённость по умолчанию**: обработчик требует маркер, если не включён в явный перечень открытых: `GET /health`, `GET /v1/hosts`, `GET /v1/hosts/{id}`, `GET /v1/hosts/{id}/reviews`, `POST /v1/users`, `POST /v1/auth/token`, `POST /v1/auth/refresh`.
- **Пароли**: только хеш функции для паролей **Argon2id** с солью и настраиваемой стоимостью; общие хеш-функции (SHA-256, MD5) запрещены.

**Определяющий довод** — `NFR-02` целиком: короткий маркер доступа выполняет срок 15 минут без обращения к хранилищу, а обновляющий маркер в базе позволяет прекратить доступ при выходе — без новой службы: база данных в системе уже есть.

## Последствия

**Положительные.** Проверка прав на каждом запросе не обращается к хранилищу. Окружение не прирастает службой. Выход и смена пароля прекращают продление доступа. Один способ передачи маркера для браузера, тестов и OpenAPI; защита от CSRF нужна только на `/v1/auth/refresh`, и её даёт `SameSite=Strict`.

**Отрицательные.** **Маркер доступа нельзя отозвать до истечения срока**: после выхода он действует до 15 минут. Снятие роли модератора вступает в силу тоже до 15 минут спустя. Данные маркера подписаны, но не зашифрованы — в него нельзя класть ничего, кроме идентификатора и роли. Утечка секрета подписи компрометирует все маркеры — нужна смена секрета и повторный вход всех. Обновление маркера — обращение к базе раз в 15 минут на пользователя.

**Что пересмотрит решение.** Требование мгновенного отзыва доступа (например, блокировка хоста по жалобе с немедленным эффектом); несколько экземпляров сервиса с разными секретами — переход на асимметричную подпись; появление единой системы входа в вузе или требование входа через внешнего поставщика.
