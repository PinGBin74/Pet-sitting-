# Агрегаты

## Бронь (Booking) — основной агрегат

**Корень**: `Booking`
**Контекст**: Бронирование

### Состав

| Элемент | Вид | Почему так |
|---|---|---|
| `Booking` | Сущность, корень | Имеет тождество: «какая именно бронь» — осмысленный вопрос |
| `StayPeriod` | Значение | Дата заезда и дата выезда. Два периода «10–14 ноября» — одно и то же. Интервал полуоткрытый по ночам: выезд 14-го и заезд 14-го не пересекаются |
| `BookingStatus` | Значение (перечисление) | `requested` / `confirmed` / `declined` / `cancelled` / `expired` |
| `PetSnapshot` | Значение | Копия карточки питомца на момент запроса: вид, порода, вес, дата прививки, особенности |
| `Cancellation` | Значение | Кто отменил, когда, причина (необязательна) |

Фаза подтверждённой брони — «предстоит», «идёт», «завершена» — не хранится, а вычисляется из `StayPeriod` и текущей даты.

### Инварианты

| № | Инвариант | Почему инвариант, а не правило сценария |
|---|---|---|
| И-1 | Дата выезда позже даты заезда: не меньше одной ночи | Проверяется по данным самого агрегата |
| И-2 | Подтвердить или отклонить можно только бронь в состоянии `requested` | По состоянию агрегата |
| И-3 | Отменить можно только бронь в состоянии `requested` или `confirmed`; повторная отмена не меняет состояние (`FR-09`, S9 сц. 3) | По состоянию агрегата |
| И-4 | У каждой брони есть снимок питомца (`FR-05`, S5 сц. 3) | По составу агрегата |

### Что инвариантом не является

| Правило | Почему не инвариант | Где проверяется |
|---|---|---|
| На каждую ночь периода у хоста не больше подтверждённых броней, чем его вместимость (`FR-06`, S6 сц. 3) | Нужны другие брони — другие экземпляры агрегата | Сценарий подтверждения под блокировкой хоста; способ — `ADR-0005` |
| Хост проверен | Нужен другой контекст | Сценарий: порт `HostDirectory` |
| Питомец принадлежит владельцу | Нужен другой контекст | Сценарий: порт хранилища питомцев |
| Дата заезда не в прошлом; отмена только до начала передержки (S9 сц. 2) | Нужна текущая дата — внешняя зависимость | Сценарий, с часами из `ports/clock.py` |
| Запрос без ответа истекает через 48 часов | Вызывается временем | Вычисляется при чтении; оповещение — задачей по расписанию в обработчике событий |

### События

| Событие | Когда | Что несёт |
|---|---|---|
| `BookingRequested` | Владелец отправил запрос | `booking_id`, `host_id`, `owner_id`, период |
| `BookingConfirmed` | Хост подтвердил | `booking_id`, `host_id`, `owner_id`, период |
| `BookingDeclined` | Хост отклонил | `booking_id`, `owner_id` |
| `BookingCancelled` | Владелец отменил | `booking_id`, `host_id`, момент |
| `BookingRequestExpired` | Хост не ответил за 48 часов | `booking_id`, `owner_id`. **Вызывается временем, не командой** |
| `StayStarted`, `StayCompleted` | Наступила дата заезда или выезда | `booking_id`. **Вызываются временем**; фаза вычисляется при чтении |

### Границы и ссылки

- Хост — по идентификатору `host_id`, другой контекст
- Владелец и питомец — по идентификаторам `owner_id`, `pet_id`; данные питомца — снимком
- Одна транзакция меняет один агрегат; проверка вместимости при подтверждении читает другие брони, но меняет только одну

### Почему снимок питомца внутри брони, а не ссылка на карточку

Хост соглашается принять конкретного питомца с конкретными данными. Если бронь ссылается на карточку, правка карточки после подтверждения — например, другой вес или новая особенность — молча изменит то, на что хост согласился.

Цена решения: данные питомца дублируются в каждой брони, и правка карточки не попадает в действующие брони — об изменениях владелец сообщает хосту сам.

## Хост (Host)

**Корень**: `Host`
**Контекст**: Хосты

### Состав

| Элемент | Вид |
|---|---|
| `Host` | Сущность, корень |
| `District` | Значение: район из справочника пилота |
| `PricePerNight` | Значение: цена за сутки в рублях |
| `Capacity` | Значение: число питомцев одновременно, целое |
| `HostPhoto` | Значение: ссылка на файл фото профиля |
| `VerificationStatus` | Значение (перечисление): `pending` / `approved` / `rejected` |
| `VerificationDecision` | Значение: результат, причина, модератор, момент. Хранится историей |

### Инварианты

| № | Инвариант |
|---|---|
| И-5 | Вместимость не меньше 1 (`FR-01`, S1 сц. 3) |
| И-6 | Цена за сутки больше 0 |
| И-7 | Район указан (`FR-01`, S1 сц. 2) |
| И-8 | У отклонения есть причина (`FR-02`, S2 сц. 3) |
| И-9 | Решение принимается только по хосту в состоянии `pending` |

### Что инвариантом не является

| Правило | Где проверяется |
|---|---|
| У пользователя не больше одного профиля хоста | Ограничение уникальности в базе |
| Решение принимает только модератор | Проверка роли на сервере (`NFR-02`) |

### События

| Событие | Что несёт |
|---|---|
| `HostProfileSubmitted` | `host_id`, `user_id`, район, вместимость |
| `HostApproved` | `host_id`, модератор, момент |
| `HostRejected` | `host_id`, причина, модератор, момент |

### Почему решения модератора внутри агрегата хоста, а не отдельным агрегатом «Заявка»

Признак «проверен» и записанное решение должны меняться в одной транзакции. Если решение — отдельный агрегат, возможен хост, видимый в поиске без записанного решения, или решение без смены статуса.

Цена: история решений загружается вместе с хостом. Решений по одному хосту — единицы, это приемлемо.

## Питомец (Pet)

**Корень**: `Pet` · **Контекст**: Участники

| Элемент | Вид |
|---|---|
| `Pet` | Сущность, корень; ссылка на владельца — `owner_id` |
| `Species` | Значение (перечисление): `cat` / `dog` |
| `Weight` | Значение: килограммы |
| `VaccinationDate` | Значение: дата последней прививки |

| № | Инвариант |
|---|---|
| И-10 | Вес больше 0 (`FR-03`, S3 сц. 2) |
| И-11 | Вид — кошка или собака |

Не инвариант: дата прививки не позже сегодняшней (S3 сц. 3) — нужна текущая дата, проверяется сценарием с `ports/clock.py`.

## Отчёт (Report) и Отзыв (Review)

**Контекст**: Передержка. Два небольших агрегата: у каждого свой жизненный цикл, ссылка на бронь — по `booking_id`.

| Агрегат | Инварианты | Что инвариантом не является | Событие |
|---|---|---|---|
| `Report` | И-12: от 1 до 10 фото | Бронь активна (S7 сц. 2) — другой агрегат и время, сценарий. Формат и размер файла (S7 сц. 3) — проверка на границе до создания агрегата (`NFR-06`) | `ReportAdded`: `booking_id`, `report_id`, момент |
| `Review` | И-13: оценка от 1 до 5 | Бронь завершена (S10 сц. 2) — сценарий. Один отзыв на бронь (S10 сц. 3) — уникальность `booking_id` в базе | `ReviewPosted`: `booking_id`, `host_id`, оценка |
