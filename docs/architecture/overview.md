# Обзор архитектуры

Документ для того, кто впервые открыл проект. Даёт картину целиком за десять минут чтения и ссылается на подробности. **Не повторяет** содержание диаграмм и записей о решениях.

## Что это за система

«Передержка рядом» — веб-сервис, где владелец кошки или собаки находит проверенного модератором частного хоста, бронирует передержку на свои даты и получает фотоотчёты, пока он в отъезде. Хост ведёт профиль и решает, принять ли запрос; модератор вручную проверяет хостов. Задача — заменить поиск в чатах, где нельзя проверить человека и неизвестно, как питомец проводит время ([`../requirements.md`](../requirements.md)).

Границы: один городской район, только услуга передержки, расчёты между сторонами напрямую. Онлайн-оплата, несколько районов, выгул, чат внутри платформы, мобильное приложение — вне охвата (раздел «Вне области охвата» в требованиях, `C-03`, `C-06`).

## Как достигаются требования к качеству

| Требование | Тактика | Где реализовано | Состояние |
|---|---|---|---|
| `NFR-01` 95 % поисков ≤ 300 мс | Индекс броней по хосту и датам; поиск без маркера; кеш результатов поиска — если нагрузочный замер покажет нехватку | База данных; сервис API | Запланировано |
| `NFR-02` Маркер и права | Проверка подлинности и прав на сервере; защищённость по умолчанию; `404` на чужой объект | ADR-0004 | Решено, не реализовано |
| `NFR-03` Диагностируемость | Структурный журнал JSON; идентификатор запроса | Сервис API | Решено, не реализовано |
| `NFR-04` Сохранность при перезапуске | Хранение в базе и на именованном томе; проверка готовности | ADR-0006; база данных | Запланировано |
| `NFR-05` Стоимость изменения | Разделение ответственностей; инверсия зависимостей через `ports/`; проверка границ в конвейере; порог покрытия | ADR-0003; конвейер | Решено, не реализовано |
| `NFR-06` Фотографии | Проверка типа по содержимому и размера на границе; отдача через API с проверкой прав; именованный том | ADR-0006 | Решено, не реализовано |
| `FR-06` Вместимость не превышается | Проверка и запись подтверждения в одной транзакции под блокировкой хоста | ADR-0005; база данных | Запланировано |

Колонка «состояние» меняется по мере работ; к защите проекта в ней не должно остаться «решено, не реализовано» без причины.

**Требования без тактик**: нет. Проверено при составлении таблицы.

## Защищённость

### Принципы

| Принцип | Как применяется |
|---|---|
| Наименьшие права | Процесс в контейнере не от `root`. Пользователь базы без права менять схему. В маркере только идентификатор и роль модератора (ADR-0004) |
| Защищённость по умолчанию | Обработчик требует маркер, если не включён в явный перечень открытых (ADR-0004) |
| Эшелонированная защита | Проверка данных в модели на границе, инварианты в предметной области, ограничения в базе, проверка прав в обработчике |
| Безопасный отказ | Ошибка проверки маркера или прав — отказ; ошибка проверки типа файла — файл не сохраняется |
| Минимум поверхности | Порт базы наружу не публикуется; том с фото не отдаётся веб-сервером напрямую — только через API; описание API закрыто вне разработки |

### Модель угроз: введение

| Угроза | Как может проявиться | Защита |
|---|---|---|
| Подмена личности | Запрос брони или отзыв от имени другого владельца | Подписанный маркер (ADR-0004) |
| Искажение данных | Изменение чужой брони или карточки; файл, выдающий себя за фото | Проверка принадлежности на сервере; тип файла по содержимому (ADR-0006); ограничения в базе |
| Отказ от совершённого | «Я не подтверждал эту бронь»; «модератор не одобрял этого хоста» | История решений модератора в агрегате `Host`; журнал аудита — кто и когда |
| Разглашение | Чужие брони и фото отчётов; адрес хоста по геометке в фото; контакты до подтверждения | Проверка прав и `404`; контакты только после подтверждения (`NFR-02`); удаление метаданных EXIF при сохранении фото |
| Отказ в обслуживании | Поток запросов брони к одному хосту; загрузка больших файлов | Ограничение частоты; предел размера тела 10 МБ; истечение запроса брони через 48 часов |
| Повышение прав | Хост сам ставит себе «проверен»; владелец смотрит очередь модерации | Роль модератора проверяется на сервере; поле статуса проверки не принимается из тела запроса |

### Что предусмотрено

Кода ещё нет, поэтому здесь не «сделано», а «решено»: меры приняты как правила и появятся вместе с первым кодом.

- Пароли и ключи не попадают в репозиторий: `.env` исключён, в репозитории `.env.example`
- В журнал не пишутся пароли, маркеры, телефоны и адреса — только идентификаторы
- Входные данные проверяются моделями `pydantic` на границе
- Процесс в контейнере работает от непривилегированного пользователя
- Порт базы наружу не публикуется
- Пароли — только хеш Argon2id

### Что отложено

| Что | Почему не сейчас |
|---|---|
| Проверка подлинности и прав | Нужен контракт API |
| Удаление метаданных EXIF из фото | Вместе с загрузкой фото |
| Журнал аудита | Вместе с наблюдаемостью |
| Ограничение частоты запросов | Общий счётчик требует кеша |
| Проверка зависимостей и образа на уязвимости | Вместе с конвейером доставки |
| Полная модель угроз | Введения по STRIDE достаточно для объёма проекта |

## Что осознанно не сделано

| Решение не делать | Причина |
|---|---|
| Микросервисы | ADR-0003: `C-04`; вместимость проверяется одной транзакцией |
| Вход через внешнего поставщика (VK ID, Яндекс ID) | ADR-0004: внешняя зависимость на учебном стенде; пароли — только хеш Argon2id |
| Объектное хранилище для фото | ADR-0006: новая служба и второй механизм доступа; переход — заменой адаптера |
| Оркестрация | `C-05`: практика на Compose |
| Удаление броней и отзывов | Только смена состояния: история отмен нужна для разбора жалоб |
| Сжатие и уменьшенные копии фото на сервере | Фото отдаются как есть; вернуться при жалобах на скорость просмотра отчётов |
