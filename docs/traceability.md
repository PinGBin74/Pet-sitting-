# Матрица прослеживаемости

Связывает требования из [`requirements.md`](./requirements.md) с решениями, кодом и проверками.

**Порядок обновления**: матрица правится **в том же запросе на слияние**, в котором меняется требование, решение или тест. Запрос, который добавляет тест или запись о решении и не трогает матрицу, на ревью не принимается. Полнота матрицы проверяется на защите.

**Что входит**: требования, взятые в работу, — `Must` и `Should`. Требования `Could` и `Won't` вносятся, когда их берут в работу.

**Состояния**: `Записано` → `Спроектировано` → `Реализовано` → `Проверено`. «Спроектировано» — на требование ссылается запись о решении.

Проверок пока нет ни у одного критерия: тесты появятся с ЛР 3. Ниже — критерии, которые легче всего потерять, с местом, где появится проверка.

| `AC-05.5` повторная отправка запроса | `FR-05` | ЛР 4Б: идемпотентность запроса брони |
| `AC-06.5` одновременное подтверждение | `FR-06` | ЛР 4А–5: тест с двумя параллельными подтверждениями |
| `AC-09.3` отмена накануне и в день заезда | `FR-09` | ЛР 3Б: тест с подставными часами |
| `AC-13.2` истечение ровно через 48 часов | `FR-13` | ЛР 3Б: тест с подставными часами |

## Обратная проверка: что в системе не следует из требований

### По пути пользователя

| Шаг пути (ЛР 1А) | Из какого требования следует |
|---|---|
| 2. Заполнил карточку питомца | `FR-03` |
| 3. Задал район и даты | `FR-04` |
| 4. Просмотрел проверенных хостов и отзывы | `FR-04`, `FR-10` |
| 5. Отправил запрос на бронь | `FR-05`; **входа в систему не было** → добавлено `FR-11` |
| 6. Хост подтвердил | `FR-06` |
| 7. Получил отчёты и оставил отзыв | `FR-07`, `FR-08`, `FR-10` |

Шаг 1 «Понял, что нужна передержка» происходит вне системы — требование к нему не нужно.

### По картам пути клиента и перечню ресурсов API

| Шаг пути или находка | Где найдено | Что сделано |
|---|---|---|
| Хост не видит, в каком состоянии заявка и почему отказали | Карта пути хоста, этап «Проверка» | Добавлено `FR-12` (Should) |
| Хост должен видеть входящие запросы, владелец — свои брони; отдельной истории нет | `docs/api/resources.md` | Вошло в историю `FR-06` и в `FR-05` |
| Запрос без ответа хоста никогда не заканчивается | Агрегат `Бронь`, событие «Запрос брони истёк» | Добавлено `FR-13` (Should); срок подтверждается на сессии |
| Регистрация, вход и выход не следуют ни из одной истории | `docs/api/resources.md` | Добавлено `FR-11` (Must) |
