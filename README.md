# Передержка рядом

Платформа, где владелец кошки или собаки находит проверенного модератором частного хоста для передержки на время отъезда, бронирует его на свои даты и получает фотоотчёты о питомце.

**Команда**: Ирина (@irenandko), Артур (@whohess), Антон (@PinGBin174)
**Курс**: Технологии разработки программных систем, ОмГТУ, 09.03.01
**Предметная область**: передержка питомцев у частных хостов

## О проекте

Владельцы кошек и собак, уезжающие на 2–14 дней, сейчас ищут передержку в чатах и на досках объявлений, где нельзя проверить человека и неизвестно, как питомец проводит время. Мы делаем веб-сервис для одного городского района, в котором:

- хост создаёт профиль, а модератор вручную проверяет его и ставит отметку «проверен»;
- владелец один раз заполняет карточку питомца и ищет свободных проверенных хостов по району и датам;
- владелец отправляет запрос брони, хост подтверждает или отклоняет;
- во время передержки хост публикует фотоотчёты, после завершения владелец оставляет отзыв.

Подробности — в [docs/requirements.md](docs/requirements.md).

## Как запустить

### Что нужно установить

- [Git](https://git-scm.com/)
- [uv](https://docs.astral.sh/uv/) — менеджер Python и зависимостей; нужную версию Python (3.13) он ставит сам по файлу `.python-version`
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) с Compose; на Windows — с механизмом WSL 2

Проверка: `uv --version` и `docker run --rm hello-world` выполняются без ошибок.

> **Windows:** держите репозиторий внутри WSL (`~/projects/...`), а не в `/mnt/c/...` — иначе сборка и тесты идут в разы медленнее.

### Полностью в контейнерах — одной командой

```bash
docker compose up -d --build
curl http://localhost:8080/health          # {"status":"ok"}
```

Остановить: `docker compose down`. Данные базы хранятся в томе и переживают перезапуск.

### Локально, для разработки

Сервису нужна база на порту 5432 этой машины. По умолчанию порт базы наружу не открыт: в `compose.yaml` у службы `db` раскомментируйте блок `ports`. Если порт 5432 занят (например, установлен свой PostgreSQL), замените левую часть, например `"127.0.0.1:5433:5432"`, и тот же порт укажите в `DATABASE_URL` в `.env`.

```bash
uv sync                      # поставить Python и зависимости ровно по uv.lock
cp .env.example .env         # создать локальную конфигурацию
docker compose up -d db      # поднять только базу данных
uv run python -m booking     # запустить сервис
```

Сервис — на `http://localhost:8080`, описание API — на `http://localhost:8080/docs`.

### Тесты и проверки

```bash
uv run pytest --cov=src/booking --cov-report=term-missing   # тесты с покрытием
uv run ruff format --check .                                # форматирование
uv run ruff check .                                         # линтер
uv run mypy src/                                            # типы
```

Те же проверки выполняет конвейер на каждый запрос на слияние, порог покрытия — 70 %.

## Как внести изменение

1. Обновите основную ветку: `git switch main && git pull`
2. Создайте ветку от `main`: `git switch -c feat/SCRUM-<номер>-<короткое-описание>`
3. Внесите изменения, закоммитьте по [соглашению о коммитах](CONTRIBUTING.md#формат-коммитов)
4. Добавьте запись в [CHANGELOG.md](CHANGELOG.md)
5. Отправьте ветку и откройте запрос на слияние — шаблон описания подставится автоматически
6. Дождитесь зелёного конвейера и ревью другого участника, затем слейте способом squash

Прямая запись в `main` запрещена. Подробные правила — в [CONTRIBUTING.md](CONTRIBUTING.md).
